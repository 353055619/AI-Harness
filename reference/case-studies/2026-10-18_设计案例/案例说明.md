# 案例说明 · 2026-10-18_设计案例

> 本目录是 **godw-design 插件（v0.2.0）二轮全流程实测**的完整产物副本——从需求到可交互原型走完整条流水线，两道验收门全部收敛 PASS 后自动归档。原属某企业内部项目，已做泛化脱敏处理：公司名、内部系统代号、项目专用模型词均已替换为通用词，人名与账号均为虚构模拟数据。

## 这个案例展示了什么

godw-design 是一条「需求 → 4A 架构 → 原型」的设计流水线（[插件仓库](../../../plugins/godw-design/README.md)）：

```
clarify-goal 需求澄清 → formalize 需求规格化（FR/NFR 编号，冻结）
  → 1a 需求分解 → 1b 四架构文档 + detail.json + 需求追踪
  → 1c 文字层验收门（模拟用户/开发者复现/架构师/简洁官 子智能体评审，迭代到收敛）
  → 2a 可交互原型（JSON 模拟库/页面跳转/状态流转/角色切换）
  → 2b 原型层验收门 → 2c 收口自动归档
```

## 目录导览

| `history/` | 全过程：需求分解两腿、问题登记表（gate-registry）、两门各轮验收报告、过门快照、33 条裁决记录、收口报告 |

## 实测成绩（本案例）

- 门1（文字层）五轮收敛：登记问题 open 36→7→0，PASS；
- 门2（原型层）两轮收敛：open 10→2→0，PASS；
- 评审评委抓出的典型真问题：合并付款未重校白名单（击穿 NFR）、自动完结死路径（条件永假）、改派候选未按环节角色过滤（死单）；
- 对比首轮实测（同需求、旧版机制）：8 轮评审全 FAIL 无法收敛——收敛登记表 + 评审锚定卡 + 探索/收敛两期节奏的机制进化即由此驱动。

## 阅读建议

- 想看流程产物结构：从 `原始需求.md` 顺读到 `原型系统/`；
- 想看 Agent 自进化评审怎么工作：`history/gate-registry.md`（问题怎么被登记、修复、收敛）+ 任一 `gate-*.md`（评委原话与评分）；
- 想直接体验原型：浏览器打开 `原型系统/prototype.html`，右上角切换账号角色。
