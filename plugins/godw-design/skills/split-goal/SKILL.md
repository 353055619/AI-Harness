# GOAL 分解 → GOAL-4A.md + GOAL-UX.md

## 输入（强制，缺则报错退出，不反问用户）

- `.agents/GOAL.md` 必须已存在且两章齐全（由 clarify-goal 首建定稿）。不存在或第二章为空 → 直接失败退出，提示先走 clarify-goal。

## 分解纪律

1. **只分解不发明**：两腿的每一条内容都要能在 GOAL.md（以第二章为主、第一章原话为线索）找到出处；GOAL.md 没说的不要推测补全。
2. **缺口显式化**：下游需要但 GOAL.md 未覆盖的点，在对应腿的「待澄清」小节列出（每条注明为什么需要、影响下游哪个决策），交回调用方决定问用户还是按默认裁决——本技能自己不问、不编。
3. **GOAL.md 本技能只读不改**：受控修订通道只有一个（同插件 make-design 的需求回流协议：门反馈驱动、交付边界守护、演进记录留痕），不在本技能；日常分解迭代只改两腿文件。
4. **同源一致**：角色清单两腿必须一致（体验腿的用户类别 ⊆ 架构腿的角色清单）；实体、状态、流程的命名两腿保持同一套词。

## 完成门

- 两腿字段无空白、无占位桩；「待澄清」小节允许为空列表。
- 同源一致检查通过（角色对齐、命名一致）。
- 返回两腿路径与各自要点摘要，后续动作由调用方决定。
