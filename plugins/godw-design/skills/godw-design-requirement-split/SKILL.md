# 需求分解 → 两腿 + 身份卡.md + 参考资料/INDEX.md

## 输入（强制，缺则报错退出，不反问用户）

- 实例的 `原始需求.md`（`design/change/<实例>/` 下）必须存在且含 FR/NFR 编号。不存在 → 直接失败退出，提示先走 godw-design-requirement-formalize。
- 实例定位：`design/change/` 唯一实例自动定位，多实例时须由调用方指明实例名。
- 参考资料（如有）：实例 `参考资料/` 下已归位的文件（formalize 归位）——INDEX 建账对象；目录不存在或为空则跳过建账。

## 分解纪律

1. **只分解不发明**：两腿的每一条内容都要能在原始需求.md（含其 FR/NFR 编号条目）或**已裁决吸收的 GR-xx 增量**（DECISIONS.md 有出处的）找到来源；两处都没有的不要推测补全。
2. **缺口显式化**：下游需要但上游未覆盖的点，在对应腿的「待澄清」小节列出（每条注明为什么需要、影响下游哪个决策、关联的 FR/NFR），交回调用方决定问用户还是按默认裁决——本技能自己不问、不编。
3. **原始需求.md 本技能只读不改**：受控通道只有 make-design 家族的回流协议 v2（两腿吸收+GR 编号+DECISIONS 出处）；本技能日常迭代只改两腿。
4. **同源一致**：角色清单两腿必须一致（原型腿的用户类别 ⊆ 架构腿的角色清单）；实体、状态、流程的命名两腿保持同一套词（术语以实例 `术语.md` 为准）。
5. **GR 继承**：重跑/更新时，两腿是「原始需求分解 + 已裁决 GR 增量」的并集视图——GR 部分保留并标注 GR 编号出处。
6. **出题人不看答案**：身份卡与考题只从 `原始需求.md` 派生，不读 4A架构/、不读 detail.json（此时也还没有）；角色目标用原始需求原话，不设计流程。
7. **冻结物不重产**：`身份卡.md` 已存在则跳过不覆盖（产出即冻结；重建=用户手动删除后重跑，或开新实例）；两腿与 INDEX 照常更新。

## 输出（严格模板，可重复运行覆盖更新；落实例 `history/`）

```markdown
<角色 | 目标 | 关键权限/可见范围>（关联 FR-xx）

## 业务实体
<核心实体及其关键属性/状态的清单>

## 核心流程
<流程名 | 触发角色 | 步骤要点 | 业务规则/异常分支>（关联 FR-xx）

## 约束与非功能需求
<性能/安全/合规/技术栈/集成等硬约束>（关联 NFR-xx）

## 待澄清

```

### history/需求-原型输入.md（原型腿——给 2a 原型）

```markdown
# 需求·原型输入

> 派生自 原始需求.md（+已裁决 GR 增量），只分解不发明；可随迭代修订。

## 用户类别
<用户类别 | 是谁 | 来做什么 | 成功长什么样>（与需求-架构输入 角色清单同源）

## 关键旅程
<旅程名 | 用户类别 | 步骤串（含入口→操作→反馈→去向）>（关联 FR-xx）

## 页面雏形
<页面 | 服务哪段旅程 | 必须出现的元素/动作>（不必是完整清单，原型段按 detail.json 扩展）

## 交互预期
<跳转/状态反馈/模拟数据等方面的明确预期；没提的不假设>

## 待澄清
<上游未覆盖、原型设计必需的点，每条注明影响>
```

### 身份卡.md（实例根，产出即冻结——gate 评委的角色/考题唯一来源）

```markdown
# 身份卡 · <设计名>

> 1a 从 原始需求.md 一次产出并冻结；门1/门2 共用；出题人不读 4A。修改=用户手动带外，或删卡后重跑 1a。

## 一、身份卡组（每卡四句，不放决策——决策在原始需求与 DECISIONS）

### <角色名>（来源：原始需求 §2 用户与对象 / FR-xx）
- 要办成什么：<目标原话提炼，一句>
- 最怕/最烦什么：<一句>
- 懂多少：<第一天来的 / 干了三年，一句>
- 卡住了怎么办：<翻文档 / 问人 / 放弃，一句>

（覆盖位自查：天天用的、低频用的、第一天新人、审批管理方、后台维护（配规则/清脏数据/导出）、生态角色（管理员/运维/审计/外部集成）——原始需求点名角色全收，必然存在但未点名的按位补齐，补的注明「推导」及依据）

### 找茬者（坏法清单，非人物卡）
<按业务实例化逐条列出：填错漏填 / 中途退出再进 / 两人同单并发 / 越权看别人 / 流程中途规则变 / 截止最后一分钟 / 0 条与一万条极端量——每条注明关联 FR>

纪律（随卡下发评委）：只看自己该看的材料；意见必须带文档位置（无位置不算数）；身份间互不看输出。

## 二、考题（六类，只从原始需求目标出；发目标句不发流程——流程是设计稿该给的答案）

<题号 T-xx | 类型 | 目标句（办成什么事）| 关联角色 | FR-xx>
（①走通一条路 ②走歪了怎么办 ③从中间接手 ④查一个数 ⑤改一个规则 ⑥照图搭〔由 dev-reproducer 执行，此处只留目标句〕；不适用的类型标「不适用+一句理由」，不得静默缺类）

## 三、身份×题矩阵（只填该角色真会做的格子）

| 题号 | T-01 | T-02 | … |
|---|---|---|---|
| <角色> | ✓ |  | ✓ |
| 找茬者 |  | ✓ |  |
```

### 参考资料/INDEX.md（登记账；`参考资料/` 有文件才建，无则跳过）

```markdown
# 参考资料登记账 · <设计名>

> 1a 对 参考资料/ 现有文件逐一编号建账；后续新资料增补行。内化走回流协议 v2（资料中明确的业务规则=界内增量→两腿吸收+GR 编号+DECISIONS 出处）；归档判据=该吸收的点全落地+冲突全裁决 → 挪 参考资料/archive/；「无需内化」也可归档注明原因。

| RF-xx | 文件 | 是什么 | 影响 FR/NFR | 重要度 | 内化去向（文档位置/GR 号） | 状态（待内化/已内化/无需内化） | 冲突与裁决 |
|---|---|---|---|---|---|---|---|
| RF-01 | <文件名> | <一句> | FR-03 | 高 | 待内化 | 待内化 | <资料间/与需求冲突→DECISIONS 裁决号；无则 —> |
```

（四文档引用资料一律用 RF 编号不用路径——归档挪位不断链；RF→文件映射以本账为准。）

## 完成门

- 两腿字段无空白、无占位桩；「待澄清」小节允许为空列表。
- 同源一致检查通过（角色对齐、命名与术语.md 一致）。
- 身份卡.md 在位且合格：每卡四句齐全、考题六类无静默缺类（不适用须有理由）、矩阵每行与考题对齐、找茬者清单已按业务实例化。
- INDEX.md（有资料时）行数与 `参考资料/` 文件一一对应；无资料时跳过并在返回摘要注明。
- 返回：两腿路径 + 身份卡/考题要点摘要（角色数、题数）+ INDEX 建账情况，后续动作由调用方决定。
