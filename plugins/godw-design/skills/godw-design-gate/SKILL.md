# 设计工件验收门 → 登记表收敛 + gate 报告

## 输入（强制）

- 模式：`doc`（验收 `4A架构/` 全集：四文档+detail.json+需求追踪.md）或 `prototype`（验收 `原型系统/` 可交互原型）。
- 实例路径（`design/change/<实例>/`）。
- 实例根 `身份卡.md`（1a 冻结产物；动态评委的角色/考题/矩阵唯一来源）——**缺则失败退出**，提示先跑 1a（requirement-split）。
- 实例根 `原始需求.md`：**只给编排层**做 gap 三分流与边界判定；不下发动态评委与开发者复现官（他们的题来自冻结身份卡，不给原始需求）。
- 输出报告路径（调用方指定，如 `history/gate-arch-N.md`；N = history/ 已有同前缀最大号 +1，不覆盖不重置）。
- 登记表 `history/gate-registry.md`：不存在 → 本轮为首轮（建档轮）；存在 → 走收敛轮。

## 评审锚定卡（所有评委任务书统一附带——基准不换的载体）

每次派发，任务书前置附三样（从实例现文件生成）：

1. **评分锚定**：10=可直接上线 / 8=小瑕疵不碍用（=通过线）/ 5=核心受阻有绕路 / 2=核心走不通。（**仅固定评委使用**——动态用户评委以答卷表判定，不打分。）
2. **已裁决清单**：gate-registry.md 的 backlog 项 + DECISIONS.md 中「不修/已裁决」条目——评委可挑战但提级需给理由，**不许原样重提**。
3. **核心流程清单 + 需求追踪表**：判定范围（FR/GR 清单及承载链），评委按行验链不漫游。

## 评委派生（读冻结身份卡，不现场拼角色）

动态用户评委 = 身份卡.md 的身份×题矩阵中有 ✓ 的角色，一角色一个子智能体，考题 = 该角色命中的 T-xx（只发目标句，不发流程——流程是文档该给的答案，提前给了就是泄题）。超过 10 类才合并同类项（注明谁并入谁）。动态评委用 general-purpose + 任务书模板填空（见下）。

**对账（防设计发明角色）**：detail.json roles 或原型页面出现身份卡之外的角色 → 不悄悄加派，登记表记 open 条目「设计引入身份卡外角色 <名>」，走回流呈报（身份卡冻结，agent 无权改）。

## 评委结构（固定评委走预制子智能体）

**固定专业评委**（方法论不随业务变，调插件 `agents/` 预制定义，tools 锁只读；**打分与输出格式保留不变**——答卷表只替换动态用户评委）：

| 评委 | 调用 | 职责 |
|---|---|---|
| 架构评审官 | `Agent(subagent_type='godw-design:arch-reviewer')` | 七维质量评审（业务目标达成/扩展性/耦合内聚/性能/冗余/抽象/复用） |
| 简洁审查官 | `Agent(subagent_type='godw-design:simplicity-officer')` | 反膨胀砍单（页面动作/流程节点/状态/通知/接口/正文重复六区） |
| 开发者复现官 | `Agent(subagent_type='godw-design:dev-reproducer')`（doc 模式） | 只凭文档复现系统（模块/接口/表/时序），猜=blocker；**不给身份卡与原始需求** |

调用时任务传入：工件绝对路径 + 锚定卡 + 动态上下文（如门2 联动的「受影响 FR/GR 链」）。

**节奏（探索期→收敛期两段）**：

- **探索期**：首轮（建档轮）矩阵全部角色全新派发全量答卷；R2-R3 保留少量新鲜评委持续扫描。进入收敛期判据：**连续一轮新登记 <3 条且无新增 P0**。
- **收敛期**：只派**回归评委**（每类角色的任务书附登记表中该角色相关 open 问题，逐条验证「已修复且无回归」+ 重跑该角色的核心考题答卷）；新发现默认 backlog。**防松靠回归逐条验证，防漂靠少量新鲜扫描**——不再全员盲评（首轮实测教训：换评委=换基准，永不收敛）。

## 动态评委任务书（照抄改尖括号，不加引导语；前置锚定卡+身份卡四句原文）

### A. 分类用户 · doc 模式（思维业务流答卷）

> <锚定卡三样>
> 你是「<角色>」。身份卡原文：<要办成什么/最怕最烦什么/懂多少/卡住了怎么办>。
> 这是系统的架构文档集：<4A架构/ 四文档+detail.json+需求追踪.md 绝对路径>。系统还没做出来，你逐道完成分给你的考题（**只给目标句，不给路径——路径是文档该给的答案**）：
> <考题逐条：T-xx｜目标句>
> 每道题只凭文档找路，逐步作答，每步问自己：我能找到入口吗？系统让我做这步吗？做完了怎么反馈？出错了怎么办？每步结果三选一：**能做**（文档写清了）/ **卡住**（没写或前后矛盾，走不下去）/ **靠猜**（文档没写，但你脑补了一步才走得下去——照实报，这是替未来开发者暴露文档欠账）。
> 走题途中撞见的其它文档缺陷记 blockers（带位置）；合理诉求整份文档没安排记 gaps（这类更要报，你是替未来真实用户提前发现问题）。
> 只输出以下 JSON（不要其他文字）：
> {"role":"<角色>","answers":[{"qid":"<T-xx>","result":"能做|卡住|靠猜","steps":[{"step":1,"uses":"<页面/字段>","where":"<文档位置>"}],"note":"<卡住/靠猜的原因，能做则省略>"}],"blockers":["<文档缺陷具体位置和问题>"],"gaps":["<需求缺口+为什么合理>"],"suggestions":["<不阻断的建议>"]}

### C. 分类用户 · prototype 模式（实操原型答卷）

> <锚定卡三样>
> 你是「<角色>」。身份卡原文：<要办成什么/最怕最烦什么/懂多少/卡住了怎么办>。
> 这是可交互原型：<原型系统/ 路径，index.html 入口；多文件组织=index+pages/+data.js+assets/>。以该身份逐道实操考题（只给目标句）：
> <考题逐条：T-xx｜目标句>
> 逐步验证：入口找得到吗？操作后有真实反馈吗？状态真的变了吗（提交后待办是否多一条）？跳转对吗？你可见/不可见的东西符合身份吗？每步结果三选一：**能做** / **卡住**（点不下去或行为与文档矛盾）/ **靠猜**（必须脑补设计意图才能继续）。
> 管理员/运维角色走管理面运维面（用户管理/配置/日志/异常处理），没有对应页面本身就是 gap（记 gaps）。
> 可用浏览器实操；无法实操时精读 HTML/JS 推演每条交互路径后作答，并在 suggestions 注明「推演非实操」。
> 只输出以上 JSON 格式。

### R. 回归评委附加段（收敛轮，追加在对应角色任务书末尾）

> 另附登记表中与你角色相关的 open 问题清单：<逐条>。逐条验证：已修复且无回归。已修复的从你的 blockers/gaps 排除；未修复或回归的在 blockers 注明「登记项未修复/回归」。随后重跑你的核心考题（<核心题号>），按答卷表作答——核心题出现「卡住」即为 blocker。不带历史成绩入场。

## 汇总、登记表与判定（编排层自己做，不派子智能体）

1. **分波并行派发**（Agent 工具），评委互不知晓、任务书零引导（不辩护、不透露上轮结果）。**每波并行子智能体 ≤6-7 个**（二轮实测 >7 撞配额限流全挂）；评委多时分波派发，波间不需等待人工。**配额失败处理**：个别评委因配额/限流派发失败 → 在登记表记 open 条目（「待补派」）、本轮按已回收结果汇总，失败评委**下一轮 R+1 补派**——补派不算消耗安全上限轮次。
2. 收齐逐份解析（JSON 不合法返工重跑一次），更新 `history/gate-registry.md`：

```markdown
# 问题收敛登记表（<工件> · 更新于 <轮次>）
| 编号 | 类型 | 问题 | 来源角色/轮次 | 状态 |
|---|---|---|---|---|
| B-01 | blocker | <一句话> | 业务接口人 R1 | fixed(R3) / open |
| G-04 | gap(界内) | <一句话> | 社区开发者 R2 | 已吸收→GR-02(R4) / open |
| G-11 | gap(靠猜) | <答卷靠猜的补写点> | 运维 R3 | open（**靠猜不得 backlog**） |
| G-12 | gap(长尾) | <一句话> | 运维 R3 | backlog |
| S-02 | suggestion | <一句话> | 架构师 R1 | 吸收(R2) / 不收(理由) |
## backlog（不阻断放行，收口统一呈报）
```

3. **答卷登记规则**：核心考题「卡住」= blocker（B-xx，注明题号）；「靠猜」逐条登记 `G-xx（靠猜）`——靠猜是文档欠账，**必须补写文档清零，不得 backlog**；非核心题的卡住按 gap 分流。
4. **gap 三分流**（编排层判）：核心路径缺失且界内 → 回流（调 godw-design-orchestrator 的回流协议 v2：两腿吸收+GR 编号+DECISIONS 出处，登记表标「已吸收→GR-xx」）；锦上添花/边缘场景 → backlog；新用户群/新价值主张 → 越界（停止呈报用户）。
5. **blocker 准入**（评委任务书已定义）：阻断 = 核心流程走不通（含核心考题卡住）/ 数据错误 / 安全问题；其余按 gap/suggestion 报，编排层分流。升级须给理由（对照锚定卡）。
6. **判定线**：
   - 首轮 = 建档轮（不判 PASS/FAIL）。
   - 收敛轮 **PASS** = 登记表 open 状态的 blockers、界内 gaps 与**靠猜条目全部清零** + 本轮新 blockers = 0（**不论哪个评委发现，含新鲜评委**——准入已保证 blocker 均为硬伤）+ 回归评委核心考题重跑答卷**卡住=0 且无新靠猜**。**新鲜评委的答卷结果不进判定**（第一印象天然苛刻，其卡住/靠猜进登记表但不阻断），backlog 非空不影响。
7. **修订清单三轨**：blockers 修工件（按位置去重）；界内 gaps 走回流；靠猜条目补写文档（修完下轮重答该题）；简洁审查官确认的过度设计进砍单（砍出回归由下轮回归评委抓）；suggestions 择优（不收的记一句理由）。
8. 写报告（调用方指定路径）：

```markdown
# 门验收报告：<工件> · 第 N 轮（<模式>）
- 判定：建档轮 / PASS / FAIL（判定线：登记 open 清零〔含靠猜〕+ 新 blockers=0 + 核心答卷卡住=0）
- 派发：<动态角色评委 N + 回归评委 M + 新鲜评委 K + 固定评委（架构评审官/简洁审查官/开发者复现官）>
- 锚定卡版本：<已裁决清单条数/追踪表行数/身份卡角色数与题数>
## 答卷汇总（动态评委）
| 角色 | 题号 | 结果 | 卡住/靠猜要点 |
## 评分汇总（固定评委）
| 评委 | 维度 | 分 | 与上轮比 |
## 登记表变动
- 修复确认：B-03(R2)→fixed、G-04 已吸收→GR-02 …
- 新登记：B-12、G-15(靠猜→须补写) …
- 回归：B-03 修复引入新问题 → 重新 open
## 修订清单（三轨：blockers 修工件 / 界内 gaps 走回流 / 靠猜补写 + 砍单执行）
## 子智能体原话附录（JSON 全文照录）
## 下一步
PASS → 放行下一步（并提示快照）/ FAIL → 修订→godw-design-check→重验（安全上限剩余 <M> 轮）
```

## 纪律

- **独立**：评委并行互不可见；同轮不因某评委结果差提前终止其他走查。
- **无引导**：任务书照抄只填尖括号；锚定卡与身份卡是客观数据不是辩护词。
- **照录**：评委原话全文进报告附录，不删改不润色——验收报告是证据。
- **收敛≠零问题**：登记表清零即收敛；backlog 是常态，为清空 backlog 无限加料是被简洁审查官反制的对象（靠猜除外——靠猜不得 backlog）。
- **迭代即运维**：本技能本质是提前用 Agent 模拟真实用户做生产版本运维。
- **安全上限**：调用方约束（编排器为每门 5 轮）；PASS 即收敛停；每轮报告独立成文件。
- **重验评委**：修订者可看登记表与修订清单，但重验的回归/新鲜评委**不上轮成绩、不带修订说明**（只给问题清单验证修复）。
- **修订后校验**：FAIL 轮的修订完成后，由调用方（godw-design-orchestrator）调 godw-design-check，校验不过打回修订、不进评委。
