# 悬赏厅完整卷 · 需求-架构输入

> 版本 v1 · 2099-01-02 · 从原始需求 v1 提炼，供 4A 架构与 PRD 使用

## 1 角色与权限

| 角色 | 权限 | 说明 |
| --- | --- | --- |
| 楼主 | 发布悬赏、管理我的悬赏、采纳结算、浏览全部悬赏、接收消息 | 悬赏发起方，积分支出方 |
| 回答者 | 浏览全部悬赏、提交回答、接收消息 | 答案供给方，积分收入方 |
| 平台运营 | 浏览全部悬赏、下架违规悬赏 | 内容治理方，不参与积分交易 |

权限收敛原则（对应 NFR-02）：我的悬赏仅楼主可进；消息通知仅楼主与回答者可进；下架动作仅平台运营可见；越权访问一律给出无权限提示页。

## 2 业务实体

- 悬赏单：标题、描述、积分、状态（草稿、进行中、已结悬赏、已下架）、楼主、发布时间、采纳截止时间、下架原因；
- 回答单：内容、回答者、所属悬赏、提交时间、状态（已提交、已采纳、未采纳）；
- 消息记录：类型（新回答、采纳结果、积分到账、下架结果）、内容、接收角色、关联单据、时间、状态（未读、已读）；
- 积分账户：按角色记账，发布时冻结、采纳时划转、下架时退回。

## 3 核心流程

1. 悬赏发布：楼主填表，校验标题与积分区间，冻结积分，悬赏单转进行中；
2. 回答提交：回答者进入详情提交非空回答，同时给楼主生成新回答消息；
3. 采纳结算：楼主窗口内采纳一条回答，回答单分流，积分划转，给双方生成采纳结果与积分到账消息；
4. 消息通知：事件落库为消息记录，顶栏角标统计未读数，单条或全部标记已读；
5. 运营下架：平台运营填写原因确认下架，悬赏单转已下架，冻结积分退回楼主，生成下架结果消息。

## 4 约束与非功能

- NFR-01：列表与详情在 300 条悬赏规模下首屏渲染 P95 不超过 2 秒，数据一次加载、页内过滤；
- NFR-02：权限最小化，页面与动作按角色收敛，越权访问给出无权限提示页；
- 一致性：采纳结算与下架退回都是一步完成的事务动作，页面不出现双向扣减或退回不落账的中间态；
- 时间口径：采纳窗口按发布时间加 72 小时计算，消息按事件时间倒序展示。
