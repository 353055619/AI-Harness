# 业务工作台惯例（先定分区，再画页面）

调研背景（2026-10-14，survey-lofi-proto-20261014-official-community）：12 个主流 AI 原型产品无一内嵌企业工作台经验；业务域惯例最可靠出处是宜搭/飞书官方文档（中文语境四区命名）+ SAP Fiori My Inbox 与 Camunda Tasklist（国际侧 split-view 惯例）。本技能把这些惯例固化为低保真设计前置步骤。

## 使用时机

html-wireframe / html-prototype 遇到**工作台类**系统（电子流、审批流、任务处理、工单、待办中心）时，出任何页面前先做下面两步；其他系统类型跳过本技能。

## 第一步：分区惯例（别发明，先用行业答案）

凡有「流转」语义的单据（申请/审批/工单/任务），任务中心默认四区（出处：钉钉宜搭「流程任务中心」官方四区 + 飞书审批小组件四列表，两者几乎一一对应）：

| 分区 | 含义 | 谁在看 |
|---|---|---|
| 待我处理 | 等我审批/处理的 | 审批人/处理人 |
| 我已处理 | 我处理过的（可追溯） | 审批人/处理人 |
| 我创建的 | 我发起的（盯进度） | 申请人/发起人 |
| 抄送我的 | 知会我的（只读为主） | 被抄送人 |

- 四区是**下限**不是上限：系统有多类流转单据时可按单据类型分组，但不要出现第五个语义重叠区。
- 国际语境对应 My Inbox / My Requests / CC'd to me，命名可本地化，语义不可漂移。

任务处理页布局默认 split-view（出处：SAP Fiori My Inbox + Camunda 8 Tasklist 官方模式）：

- **左列表右详情**双栏；列表按过滤器收窄（分配给我/我的组/未分配——Camunda 惯例；或按优先级/创建人/日期——Fiori 惯例）
- 详情面板带**决策按钮组**（通过/驳回，主次分明，驳回必带意见输入）
- 窄屏降级为列表→详情二级跳转

## 第二步：角色可见性矩阵（RBAC 分区）

同一页面不同角色看到不同东西。出页面前先落一张矩阵（页面对齐调用方给的页面清单，如 ARCH-4A.md 衔接块 pages）：

| 页面\角色 | 申请人 | 审批人 | 抄送人 | 管理员 |
|---|---|---|---|---|
| 发起申请 | ✓（可编辑） | ✗ | ✗ | ✗ |
| 待我处理 | ✗ | ✓（可审批） | ✗ | ✓（全量只读） |

- ✓ 要标注能做什么（浏览/编辑/审批），不是只打勾
- 原型里必须**可切换角色实际验证**：切到抄送人时决策按钮必须消失，而不是置灰了事
- 矩阵与上游输入冲突时以上游为准（如衔接块 roles.permissions），并在交付说明里记一句差异

## 常用构件惯例（画到对应位置时查）

- **状态徽标**：每个单据状态一个固定色（草稿灰/进行中蓝/通过绿/驳回红），全局一致不换色
- **流程时间线**：详情页展示审批进度（谁-何时-动作-意见），驳回点高亮（出处：飞书审批详情）
- **批量操作**：列表多选 + 顶部批量动作（仅审批人区出现）
- **空态**：每个分区都要有（「暂无待办，去发起一个 →」带去行动作，不是裸「暂无数据」）
- **数字徽标**：待我处理区在导航上带未处理计数

## 纪律

- 惯例优先于创意：工作台用户要的是「跟用过的系统长一样」，先锋布局在这里是负资产。
- 每条惯例应用到页面时，不用注释出处（那是本技能的事，不是页面的事）。
- 本技能只管「业务分区与可见性的行业答案」；页面保真度、交互完整性归 html-wireframe / html-prototype。
