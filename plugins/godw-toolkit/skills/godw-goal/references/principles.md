# 交付第一性原理与诉求澄清法

> 第一性原理由 godw 提出（2026-10-01），适用于一切交付对象；诉求升级法同日由 godw 补充，是第一性原理的执行方法。

## 第一性原理

汇报是交付：向用户交付信心产品，和交付物理产品，第一步完全一样——搞清楚用户要什么。这一步没做，后面所有技巧都是零，甚至是负的（精美地包装了错误的东西）。

## 诉求升级法（第一步的执行方法）

godw 的原始表述：

> 用户目前有诉求，我们要搞清楚用户所处的大背景是什么，我们把自身放到这个大背景下（与用户相同的情景中），那么我们也会产生类似的诉求，我们要进一步把这个诉求整理更清晰，更有远见。用户可能思考不充分，在他那个条件下只想做一件小事，但是我们设身处地分析后，他可以做一件更充分、更大的事情，可以拿到自己原本想要更多的东西。然后我们跟用户确认过后，就从这个更好的诉求出发点出发，这才叫更优的诉求澄清。

四步：

1. **显性诉求**：他要什么、给谁、达成什么；用他的口径复述。口径 = 他关心的指标、单位、时间尺度——用他的口径说，他才听得进、转述得出。
2. **挖大背景**：他为什么**现在**提（时机往往暴露动机）；这件事挂在他哪件大事上、走到什么阶段（定位我们自己所处的位置）；他当下最怕什么、最想守住什么。搞不清就换位倒推：坐在他的位置，最怕被问住的问题是什么。
3. **设身处地**：把自己放进他的情景。处在同样位置，我们也会产生的诉求是什么——那个诉求往往比字面诉求更根本。
4. **升级与确认**：把诉求整理得更清晰、更有远见；他的条件允许时，提出比他所求更充分的方案。升级的判据只有一条：他能因此拿到比原本想要的更多。升级点必须过用户确认这关；用户拒绝升级就按原诉求做（他自有理由），确认后才从更好的出发点出发。

边界：升级不是加戏，不确认不出发；字面诉求已清晰且确无升级空间的小任务，直接进 spec，不硬挖。

## 示例

- 字面诉求："帮我做个周报页。"
- 大背景：项目处于风险期，领导每周追问进展，用户每次手工整理数据。
- 设身处地：他要的不是"一个页"，是"领导别再来问、自己别再手工整理"。
- 升级诉求：自动汇总数据的进展看板，领导随时自己看，不用等周报。
- 确认后，出发点从"一个静态周报页"变成"随时可看的看板"——同样一次交付，拿到的更多。

## 八个交付技巧（每条的前提都是第一步）

1. **结论先行**：把他要的答案放第一句。
2. **数字说话**：用他的口径量化——他的指标是什么单位，就说什么单位。
3. **带选项不带问题**：他要的是省心的决策，不是一道新的难题。
4. **坏消息不过夜**：他要的掌控感，一旦被外部消息先打破，就是事故。
5. **三段式决策汇报**：结论 → 数据 → 计划，是他做决策的最短路径。
6. **备好三个版本**：他的时间给多少，就交付多少。
7. **交付完说清你要什么**：要决策、要资源，还是仅同步。
8. **主动定节奏**：按时交付的供应商才赢得长期信任。

## 5Why 组合链（2026-10-07 增补，调研源 sess_481e9315，素材镜像 internel/reference/）

诉求升级法四步是骨架，组合链是提问引擎。5Why 只覆盖"追因"一步，成熟实践按目的组合：

| 目的 | 方法 | 一句话要领 |
|---|---|---|
| 让用户说真话 | Mom Test | 问过去具体行为，不问未来假设 |
| 层层追因 | Laddering | 属性→后果→价值观（功能→目标→顾虑→动机） |
| 还原决策 | JTBD 切换访谈 | "接下来发生了什么"走时间线，四大力（push/pull/anxiety/habit） |
| 组织散点 | OST（Teresa Torres） | 机会解决方案树 |
| 优先级量化 | KANO | 正反配对问卷 + Better-Worse 系数 |

坑与停止线：连环 why 变审问、诱导编造（配事实提问解毒）；"5"只是 3~7 层经验值；问到动机/行为/事实层再问即猜测；能预测下一个答案就停。专家级建议：用"tell me more / give me an example"替代裸 why。
