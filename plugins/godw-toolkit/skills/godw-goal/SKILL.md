# 定目标 → .agents/GOAL.md（一次定稿）

## 输入（强制，缺则问用户）

- 原文文本：`godw-goal "xxx"`；或
- 文件路径：`godw-goal .agents/GOAL.md`（取第一章原话为输入）

## 澄清引擎（5Why + Mom Test 组合链，方法论见 references/principles.md）

**第一性认知**：用户表达的是方案而非需求（"更快的马"→真需求是"更快更省地到达"）。第一章照录的方案只是线索，要沿链路挖到终点：**功能 → 目标 → 顾虑 → 底层动机/价值观**（Laddering 手段-目的链）。

提问纪律四条：
1. **问事实不问假设**（Mom Test）：问过去具体行为（"上次是什么情况？当时怎么做的？"），不问未来假想（"你会用吗"）。
2. **追因用展开不用审问**：连环 why 易变审问、诱导编造合理理由——改用"展开讲讲 / 举个例子 / 接下来发生了什么"（时间线还原，JTBD 式）；不满场景问"是什么让你放弃"而非"为什么放弃"。
3. **关键层多方向**：单一因果链是 5Why 的坑，关键层位横问几个方向（为什么树）。
4. **停止标准**：问到动机/行为/事实层面、再问就是猜测即收（"5"只是 3~7 层经验值）；能预测用户的下一个答案时停。

一次一问，问到约 95% 信心收口；升级点（比字面诉求更充分的方案）必须过用户确认，拒绝升级就按原诉求做；字面诉求已清晰且确无升级空间的小任务直接落盘，不硬挖。

## 输出（严格两章，一次定稿）

```markdown
# GOAL

## 第一章 原始目标
<用户原话，一个字不改>

## 第二章 澄清目标
给谁 · 达成什么 · 交付形式（markdown/html/archify/video）· 口径与约束
（纯澄清目标，无维度无权重）
```

## 定稿铁律

- **执行完即定稿**：澄清收口后**首建** `.agents/GOAL.md`，两章一次写全（guard 对不存在的 GOAL.md 放行首建；存在即冻结）。无 update 模式、无修订史文件、无解锁钥匙。
- 用户确需修改：手动编辑文件（带外行为，godw-loop-start 每轮重读自然生效）。
- 完成门：两章字段无空白、无占位桩。
- 交还调用方收尾：godw-loop-init 场景由 init 继续跑 /init、godw-loop-doc 初建与门禁自检；独立调用场景提示用户手动启动循环（/godw-loop-start，或项目内自循环 workflow godw-loop-round——init 收尾已注册）。
