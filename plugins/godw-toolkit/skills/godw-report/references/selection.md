# 格式选型与验证关

## 判定表

| 格式 | 什么时候 |
|---|---|
| markdown | 书面批阅、决策文档、自用存档 |
| html | 数据看板、演示页、要给人浏览的站 |
| archify | 架构 / 流程 / 时序 / 数据流 / 生命周期五类图 |
| video | 30–90 秒讲解与汇报动画 |

## 思想关（输出前逐条过，缺一不过）

结论前置；1 分钟读完核心；数字用他的口径；补充材料附件化。

## 验证关（原 godw-package 完成门，2026-10-04 并入）

- 每种格式按对应格式技能 reference 的验证节执行，证据落盘；没有证据不得宣称完成。
- 独立复核：复核者只看证据（截图、自检 JSON、抽帧图）不看结论，逐项对上才标「过」；自己写的不算复核——LLM 会自我附和。
- delivery.md 验证结论两栏：已验证（附证据路径）/ 未覆盖（如实列出）。
- web/html 门（2026-10-06 起，强制，无可选）：每件 html 产出后跑 `node ~/.agents/plugins/impeccable/cli/bin/cli.js detect <html…> --json`（impeccable 4.5.0，纯离线无需 API key，58 条反模式规则），JSON 输出整体落盘为证据件；退出码 0=过，2=有失败级反模式——先修复重跑，确属设计取舍的逐条在验证台账记裁决，1=检测本身失败不得标过；severity=advisory 的条目不阻断。证据路径与逐条裁决进 delivery.md 验证两栏。

## slop 清单（G2 的执行清单；借 deepseek-harness docs/AGENTS.md，2026-10-04 收编）

1. 重复内容只留一个家，其余改链接
2. 历史过程不进正文——正文只写当前事实
3. 不写实施状态注记（「已完成！」「未来将」——状态会腐烂，目录和文件本身就是状态）
4. 删推理过程，留结论与理由
5. 一段只说一件事，多义段落拆分
6. 强调通胀：满篇加粗等于没有重点
7. 当源文件/生成物存在时，不手抄目录与清单，改链接
8. 交付腔：无 AI 味、无技术黑话（业务视角重写，不是删词）
